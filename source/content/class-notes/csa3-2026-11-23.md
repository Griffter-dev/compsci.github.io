## 1. Object-oriented design (OOD)

In **object-oriented design**, programmers start by deciding **which classes** they need, then decide the **data** (instance variables) and **behaviors** (methods) of each class.

A quick trick for reading a problem description:

| Look for… | It usually becomes… | Example |
|---|---|---|
| **Nouns** (things) | Classes or instance variables | *student*, *name*, *GPA* |
| **Verbs** (actions) | Methods | *enroll*, *print*, *update* |

> *"A **library** keeps track of **books**. Each book has a **title**, an **author** and whether it is **checked out**. Members can **check out** and **return** books."*
>
> Classes: `Library`, `Book`. Book's instance variables: `title`, `author`, `checkedOut`. Methods: `checkOut()`, `returnBook()`.

## 2. UML class diagrams

Classes can be described informally, but programmers also use formal systems like **UML (Unified Modeling Language)**. A UML class diagram is a box with three parts: the **class name**, the **attributes** (instance variables) and the **methods**.

```text
+---------------------------------------+
|               Person                  |
+---------------------------------------+
| - name : String                       |
| - email : String                      |
| - phoneNumber : String                |
+---------------------------------------+
| + Person(String, String, String)      |
| + getName() : String                  |
| + setName(String) : void              |
| + toString() : String                 |
+---------------------------------------+
```

- `-` means **private** and `+` means **public**.
- `name : String` means the variable `name` has type `String`.
- `getName() : String` means the method returns a `String`.

## 3. Abstraction

**Abstraction** reduces complexity by focusing on the main idea. It **hides details that don't matter** for the question at hand and **brings together the related details that do**.

A UML diagram is an abstraction: it shows a class's attributes and methods but **not how the methods are implemented**. You use abstraction every day in Java: you call `Math.sqrt(25)` or `turtle.forward()` without knowing the code inside them.

- **Data abstraction:** naming and grouping related data (a `Person` object instead of three loose Strings).
- **Procedural abstraction:** naming a process as a method, so you can use it without knowing its steps.

## 4. Impacts of program design

**System reliability** means a program performs its tasks as expected under stated conditions, without failure. It's hard to guarantee, so programmers should **test with many different conditions**:

- normal inputs (a typical value),
- **boundary** inputs (0, empty strings, the largest allowed value),
- invalid inputs (negative numbers, `null`).

**Code reuse and licensing:**

- **Open-source** code is published for others to use for free, but it still comes with a license with rules to follow (for example, giving credit).
- Code that isn't open source requires **permission**, and often a **purchase**, before you put it in your program.
- **AI-generated code** raises new issues: it can contain bugs or security holes, it may resemble someone else's licensed code, and you're still responsible for understanding and testing it.

## 5. Anatomy of a class

```java
public class Person              // class header: public class ClassName
{
    // 1. instance variables (the object's data)
    private String name;
    private String email;
    private String phoneNumber;

    // 2. constructors (set up a new object)
    // 3. methods (the object's behaviors)
}
```

- The **class header** is `public class` followed by the class name. By convention, class names start with a **capital letter**.
- The body goes between `{ }`.

### Instance variables

- Usually the first thing in the class body.
- **Each object gets its own copy**, which is what makes one object different from another (two `Person` objects can have different names).
- Declared **`private`** so only code inside this class can use them directly. This is called **encapsulation**: other classes must go through public methods, which protects the data from being changed incorrectly.

| Keyword | Who can use it |
|---|---|
| `public` | Any class |
| `private` | Only code inside this class |

## 6. Constructors

A **constructor** runs when an object is created with `new`. Its job is to give the **instance variables their starting values**.

- Same name as the class.
- **No return type**, not even `void`.
- Usually `public`.

```java
public Person(String initName, String initEmail, String initPhone)
{
    name = initName;
    email = initEmail;
    phoneNumber = initPhone;
}
```

```java
Person p = new Person("Ada", "ada@email.com", "555-1234");
```

### The default constructor

If you **don't write any constructor**, Java gives the class a **default constructor** with no parameters. It sets instance variables to their **default values**:

| Type | Default value |
|---|---|
| `int` | `0` |
| `double` | `0.0` |
| `boolean` | `false` |
| `String` and other objects | `null` |

As soon as you write **any** constructor, Java no longer gives you the free one.

### Overloaded constructors

A class can have several constructors with different parameter lists:

```java
public Person()                   // no-argument constructor
{
    name = "Unknown";
    email = "";
    phoneNumber = "";
}
```

## 7. Writing methods

Methods define the **behavior** of a class and can use the instance variables.

```java
public returnType methodName(parameters)
{
    // method body
}
```

### void methods

A method that **doesn't return a value** has the return type `void`. The statement `return;` (with nothing after it) can end a void method early.

```java
public void print()
{
    System.out.println("Name: " + name);
    System.out.println("Email: " + email);
}
```

### Methods that return a value

The return type is the type of value sent back. **Every possible path** through the method must reach a `return` statement with a value of that type, or the code won't compile.

```java
public boolean hasEmail()
{
    if (email.length() > 0)
    {
        return true;
    }
    return false;          // needed: the method must return on every path
}
```

`return` immediately ends the method. Any code after it doesn't run.

## 8. Accessors (getters) and mutators (setters)

Since instance variables are `private`, classes provide public methods to read and change them.

| | Accessor / getter | Mutator / setter |
|---|---|---|
| Purpose | **Return** an instance variable's value | **Change** an instance variable's value |
| Return type | Same type as the variable | `void` |
| Parameters | None | The new value |
| Name | `get` + variable name, like `getName()` | `set` + variable name, like `setName(...)` |

```java
// instance variable: private String name;

/** Returns this person's name. */
public String getName()
{
    return name;
}

/** Sets this person's name to newName.
 *  @param newName the new name
 */
public void setName(String newName)
{
    name = newName;
}
```

Setters are a good place to **check for bad values**, like refusing a negative score. That's one reason encapsulation is useful.

## 9. toString

Every class has a `toString` method, even if you don't write one (like the default constructor, it comes for free). Java **calls it automatically** when an object is printed or joined to a String.

The default version prints something unhelpful like `Person@1b6d3586` (the class name and a code based on its memory location). Write your own to return useful text:

```java
public String toString()
{
    return name + " (" + email + ")";
}
```

```java
Person p = new Person("Ada", "ada@email.com", "555-1234");
System.out.println(p);          // Ada (ada@email.com)
```

`toString` should **return** the String, not print it.

## 10. How to call a method

```text
Calling from main or another class?
├── YES → Is it a static method?
│         ├── YES → ClassName.method()     e.g. Math.random()
│         └── NO  → object.method()        e.g. yertle.forward()
└── NO (calling from a method in the same class)
          → method()                       e.g. print()
```

## 11. Passing and returning object references

Programs usually have many classes that work together:

- Objects of one class can be **instance variables** of another class.
- Objects can be **passed as arguments** to methods and **returned** from methods.

### Objects as instance variables

A `Person` could have an `Address` instance variable, and `Address` is its own class with `street`, `city`, `state` and `zipCode`. This is called a **has-a** relationship: a Person *has an* Address.

```java
public class Person
{
    private String name;
    private Address home;     // an object as an instance variable
}
```

### What does a variable actually store?

| Variable type | What it stores |
|---|---|
| **Primitive** (`int`, `double`, `boolean`) | The **actual value**, like `42` |
| **Object / reference** (`String`, `Person`, …) | A **reference**: the memory address where the object's data is found |

That's why object variables are drawn with an **arrow** pointing to a box: the variable holds the arrow, not the box.

### Java passes arguments by value

When you call a method, each argument is **copied** into the parameter.

- For a **primitive**, the method gets a copy of the value. Changing the parameter **doesn't** change the caller's variable.
- For an **object**, the method gets a copy of the **reference**. Both point to the **same object**, so calling a mutator through the parameter **does** change the original object.

```java
public static void rename(Person p)
{
    p.setName("Grace");     // changes the SAME object the caller has
}

public static void addOne(int n)
{
    n = n + 1;              // only changes the copy
}
```

## 12. Aliases

When two variables refer to the **same object**, they are **aliases**. Changing the object through one variable changes what you see through the other:

```java
Person a = new Person("Ada", "a@x.com", "1");
Person b = a;               // b is an alias: same object, NOT a copy
b.setName("Grace");
System.out.println(a.getName());   // Grace
```

But if you **reassign** a variable with `=`, it now points somewhere else, and the link is broken:

```java
b = new Person("Linus", "l@x.com", "2");  // b points to a new object
b.setName("Bob");
System.out.println(a.getName());   // still Grace
```

Inside a method, `p = new Person(...)` only changes where the **parameter** points, not the caller's variable.

## Key terms

| Term | Meaning |
|---|---|
| Class | A blueprint that defines data and behavior |
| Object / instance | One specific thing made from a class with `new` |
| Instance variable | Data each object stores its own copy of |
| Constructor | Code that runs with `new` to set starting values |
| Encapsulation | Keeping data `private` and controlling access with methods |
| Accessor / mutator | Getter that returns a value / setter that changes one |
| Abstraction | Hiding details to focus on the main idea |
| Reference | The memory address an object variable stores |
| Alias | Two variables referring to the same object |

## Common mistakes

- Giving a constructor a return type: `public void Person(...)` is a **method**, not a constructor.
- Re-declaring the instance variable inside the constructor: `String name = initName;` creates a **local** variable and leaves the instance variable `null`.
- Forgetting to return on every path in a non-void method.
- Printing inside `toString` instead of returning a String.
- Thinking `Person b = a;` makes a copy. It makes an **alias**.
- Making instance variables `public` (on the AP exam, they should be `private`).
